# AI 原生专科随访 · 演示样品 v0.3

> 首页“一眼看懂”：前后对比、用医院自己的量表文档当场核对、时间账计算器；“科室看板”展示半年模拟数据。
>
> 这是给医院看价值用的可点样品，**不是交付成品**。病人和数据都是虚构的；量表文字与分级仍是草案，需医院确认。站内“待确认”页列出了 15 条需医院拍板的事项。

把一份“7 个健康管理系统 + 210 个模块”的医院需求草图，重新想成 AI 时代的样子：
**不做七个系统，只做三样东西——时间线、技能包、角色。**

在线体验：https://changrong996-droid.github.io/ai-native-clinic/

## 核心想法

| 传统做法 | 这里的做法 |
|---|---|
| 先建几十张表、画菜单、写表单 | 每个患者一条只追加的**时间线**，填表、结果、签字、随访都是事件 |
| 每个量表写一套代码 | 每个量表是一个**技能包文件**（`skills/*.json`）：题目、计分、连续分级、危机规则、患者版/医生版文案、随访规则 |
| 7 套系统、17 个公共模块 | 7 个**角色**挂不同技能包，共用同一条时间线；加科室 = 加文件 |
| 随访模块、报表模块 | 随访是技能包触发的定时任务；报表是对时间线现场提问 |

## 两层分离

- **确定性层**（`engine/engine.js`）：计分、分级、危机规则、随访触发。纯函数，不调用 AI，同样输入永远同样结果。
- **语言层**（AI）：解释题目、写诊前简报、回答问题。只能引用确定性层给出的事实。
- **人**：临床结论由医生签字生效。

## 黄金用例

`tests/golden.json` 收录 25 条用例，覆盖分级边界、PHQ-9 第 9 题与 EPDS 第 10 题危机、MENQOL 小数分级和“不适用”。

```bash
npm test
```

改技能包或改引擎后都必须全部通过。

## 科室

- 更年期门诊：MENQOL + PHQ-9
- 产科：EPDS。由原型补充，医院未提供该量表；孕晚期与产后 42 天筛查点为假设。
- 新增产科只加了 `roles/obstetrics.json` 和 `skills/epds.json` 两个文件，引擎没有改动。

## 相对医院原始文档的修订

- **PHQ-9**
  - 第 9 题任一阳性即中止常规报告，转危机流程，并给出 12356 热线。
  - 分级措辞由“抑郁症”改为“抑郁症状”。
- **MENQOL**
  - 分级区间连续化：1.00 / (1,4] / (4,6] / (6,8]。
  - 修正第 20 题、第 23 题的编号笔误。
  - 性生活维度增加“不适用”选项。
  - MHT、雌激素等处方类建议仅医生端可见。
- 以上修订均为草案，须临床确认。

## 结构

```
skills/   量表技能包：phq9、menqol、epds
roles/    科室角色：menopause（更年期门诊）、obstetrics（产科，按预产期/分娩日排筛查）
engine/   确定性层
tests/    黄金用例
app/      患者端 + 医生端演示（纯静态，无后端，数据存在本机浏览器）
```

## 接入模型（可选）

医生端底部可以填写 OpenAI 兼容接口，比如本地 Ollama `http://localhost:11434/v1`，用来改写诊前简报。配置只保存在本机浏览器里。不接模型时，简报用模板生成，功能完整可用。
